# claude-skills

คลัง Claude Code skill ส่วนตัว — เก็บ pattern และตัวอย่างที่ใช้ได้จริงแล้วในโปรเจกต์อื่น เพื่อหยิบไปดัดแปลงใช้ซ้ำ
ไม่ใช่ skill ที่รันได้ทันทีข้ามโปรเจกต์ — ต้องปรับ path ก่อนเสมอ (ดู "วิธีใช้ซ้ำ" ด้านล่าง)

## ที่มา

5 skill นี้สกัดมาจากคลังความรู้ `second-brain` (ระบบ 3-tree ที่ควบคุมด้วย `CLAUDE.md` ต่อ tree)
วันที่สกัด: 2026-08-12

## แพทเทิร์นที่ใช้ (สำคัญกว่าตัวไฟล์เอง)

ทุก skill ในนี้ตามแพทเทิร์นเดียวกัน:

1. **frontmatter สั้น** — มีแค่ `name` กับ `description` เท่านั้น
   `description` ฝัง trigger phrase ไว้ในประโยคเดียวกัน (`Use when user says X, or asks Y`)
   เพื่อให้ Claude ตัดสินใจเรียกเองได้แม้ผู้ใช้ไม่พิมพ์ `/ชื่อ` ตรง ๆ
2. **skill = checklist ลำดับขั้น ไม่ใช่ที่เก็บกติกา** — ทุกไฟล์ขึ้นต้นด้วยลิงก์กลับไปยัง "กติกาต้นทางฉบับเต็ม"
   (ไฟล์ `CLAUDE.md` หรือเอกสารกติกาของโปรเจกต์นั้น) เหตุผล คือกัน**กติกาสองที่หลุดกัน** —
   ถ้าย้ายกติกามาซ้ำในตัว skill เอง พอกติกาต้นทางอัปเดต skill จะเก่าและไม่มีใครรู้
3. **ทุก skill จบด้วยขั้นตอนตรวจ** — รันสคริปต์ตรวจสถานะ/ลิงก์ก่อนถือว่าเสร็จ ไม่ปล่อยให้เช็คเอง

## รายการ skill

| skill | ทำอะไร | ผูกกับโครงสร้างเฉพาะของ second-brain แค่ไหน |
|---|---|---|
| `digest/` | นำเข้าเอกสารดิบจาก `temp/` เข้าคลัง ตามกฎลิขสิทธิ์+ตั้งชื่อ | สูง — อ้างโครงสร้าง 3 tree ตรง ๆ |
| `ship/` | ปิดงานเป็น commit ที่สะอาด, จัดกลุ่มตามหัวเรื่อง, เขียน commit message ผ่านไฟล์ | กลาง — ส่วน git workflow (แยก commit ตามหัวเรื่อง, commit message ผ่านไฟล์) ใช้ได้ทั่วไป ส่วนสคริปต์ตรวจเฉพาะคลังนี้ |
| `new-subject/` | เปิดรายการใหม่ในคลัง (วิชาใหม่) พร้อม skeleton + ลงทะเบียน | สูง — เฉพาะโครงสร้างวิชาของ `.Subject/` |

| `update-portfolio/` | ซิงก์สถานะข้ามหลายแหล่งเข้าไฟล์สรุปเดียว + บันทึกประวัติการตัดสินใจ | กลาง — **รูปแบบ** "ไฟล์สรุปคร่อมหลายแหล่งข้อมูล ต้องรันจาก root" ใช้ซ้ำได้ |

## วิธีใช้ซ้ำในโปรเจกต์ใหม่

1. คัดลอกโฟลเดอร์ skill ที่ต้องการไปไว้ที่ `<โปรเจกต์ใหม่>/.claude/skills/<ชื่อ>/`
2. เปิด `SKILL.md` แล้วแก้ 2 จุดเสมอ:
   - path ที่ชี้กลับไป "กติกาต้นทางฉบับเต็ม" — ต้องชี้ไปไฟล์กติกาจริงของโปรเจกต์ใหม่ (หรือเขียนกติกาลงในตัว skill เองถ้าโปรเจกต์นั้นไม่มี `CLAUDE.md` แยก)
   - ชื่อไฟล์/สคริปต์ตรวจท้ายไฟล์ (`check-status.ps1`, `check-links.ps1` ฯลฯ) — ถ้าโปรเจกต์ใหม่ไม่มีสคริปต์พวกนี้ ให้ตัดขั้นตอนนั้นออกหรือแทนที่ด้วยของจริง
3. `digest/` และ `new-subject/` ผูกกับโครงสร้างเฉพาะมากที่สุด — เหมาะเป็น **ตัวอย่างแพทเทิร์น** มากกว่าเอาไปวางแล้วรันได้ทันที
4. `make-exam/` และ `update-portfolio/` ผูกหลวมกว่า — ถ้าโปรเจกต์ใหม่มี "งานที่ต้องผลิตเอกสารหลายไฟล์ตามลำดับตายตัว"
   หรือ "ไฟล์สรุปที่ต้องซิงก์จากหลายแหล่ง" ปรับแค่ path ก็ใช้ได้เกือบทันที
