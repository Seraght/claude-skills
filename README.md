# claude-skills

ชุด checklist ที่ agent เดินตามได้ สำหรับ **งานความรู้ที่ทำซ้ำเป็นรอบ** — งานที่ลำดับขั้นสลับไม่ได้,
ข้ามขั้นแล้วพังแบบไม่ส่งเสียง, และจบลงด้วยเอกสารที่ต้องไปอยู่ถูกที่
ทุกตัวอ่านกติกาของโปรเจกต์ปลายทางตอนรัน จึงย้ายไปวางที่ไหนก็ใช้ได้โดยไม่ต้องแก้ไฟล์

## รายการ skill

### งานกับคลังความรู้

ผลลัพธ์คือ *เนื้อหาในคลัง* — โครงสร้าง, digest, index, roll-up

| skill | ทำอะไร |
|---|---|
| [`init-brain/`](skills/init-brain/) | สร้างคลังใหม่ — สัมภาษณ์เฉพาะส่วนที่ต่างกันในแต่ละคลัง แล้ว scaffold ทั้ง 12 องค์ประกอบ **(พิมพ์เรียกเองเท่านั้น)** |
| [`audit-brain/`](skills/audit-brain/) | ตรวจสุขภาพคลังเดิมด้วยเกณฑ์ 12 องค์ประกอบ → ให้คะแนน → ซักผู้ใช้ทีละช่องว่าง → แก้เฉพาะที่ตัดสินแล้ว — ใช้เป็นทางอัปเดตคลังหลังอัปเดต skill ด้วย |
| [`digest/`](skills/digest/) | นำเข้าเอกสารดิบจากโฟลเดอร์พักเข้าคลัง — อ่านเนื้อหาจริง, ผ่านด่านความเป็นส่วนตัว/ลิขสิทธิ์, เขียน digest, ลงทะเบียน |
| [`new-subject/`](skills/new-subject/) | เปิดหัวข้อใหม่ในคลัง — skeleton, ย่อยเอกสารตั้งต้น, เขียนไฟล์ภาพรวม, ลงทะเบียนใน index |
| [`update-portfolio/`](skills/update-portfolio/) | ซิงก์เอกสารสรุปที่คร่อมหลายแหล่ง — เทียบทีละหัวข้อกับต้นทาง + บันทึกประวัติการตัดสินใจ |

### งานสอนและวัดผล

ผลลัพธ์คือ *เอกสารที่คนอื่นเอาไปเรียนหรือใช้ประเมิน*

| skill | ทำอะไร |
|---|---|
| [`design-course/`](skills/design-course/) | ออกแบบรายวิชาย้อนจากผลลัพธ์ — ตรวจว่าวิชาติดหนี้หลักสูตรข้อไหน → เขียน CLO → ตัดสินวิธีวัดของแต่ละข้อ → จึงค่อยวางตารางสอน |
| [`make-exam/`](skills/make-exam/) | ออกข้อสอบตามลำดับที่ห้ามสลับ — ตรวจผลลัพธ์การเรียนรู้ก่อน → ซักผู้ใช้จนได้ blueprint → ร่างแนวคิดรายข้อให้ผู้ใช้เลือก → ชุดปรับจูน → เขียนทีละข้อตามงบรูปแบบ → วัดข้อบกพร่องเป็นตัวเลข → answer key → rubric → ส่งวิพากษ์ในบริบทใหม่ |
| [`make-practical/`](skills/make-practical/) | ออกข้อสอบปฏิบัติ — ตาราง alignment ของภารกิจ → ภารกิจพร้อมเงื่อนไข → checklist หรือ rating scale → เกณฑ์ผ่าน → คู่มือผู้ตรวจ |
| [`critique-mcq/`](skills/critique-mcq/) | วิพากษ์ข้อสอบปรนัยก่อนนำไปใช้ — วัดตัวเลือกก่อน แล้วรายงานทั้งรายข้อและทั้งฉบับ พร้อมฉบับแก้ รออนุมัติก่อนแตะไฟล์ |
| [`analyze-results/`](skills/analyze-results/) | วิเคราะห์ข้อสอบหลังสอบ — ผ่านด่านข้อมูลส่วนบุคคล → ความยาก → อำนาจจำแนก → ตัวลวง → ความเชื่อมั่น → ตีความตามขนาดกลุ่ม → เก็บสถิติเข้าคลังข้อสอบ |

อีกสามโฟลเดอร์ไม่ใช่ checklist แต่เป็น **reference skill** — ไม่มีขั้นตอนของตัวเอง มีไว้ให้ตัวอื่นเรียกด้วยชื่อ
เพื่อให้ความรู้ก้อนเดียวกันอยู่บ้านเดียว ไม่ต้องมีสำเนาที่ค่อย ๆ เพี้ยนออกจากกัน

| reference skill | เก็บอะไร | ใครอ่าน |
|---|---|---|
| [`brain-anatomy/`](skills/brain-anatomy/) | นิยาม 12 องค์ประกอบของคลัง | `init-brain`, `audit-brain` |
| [`assessment-layout/`](skills/assessment-layout/) | ที่อยู่ของชุดสอบ ความหมายของเลขหน้าไฟล์ และรูปร่างของ blueprint | `make-exam`, `critique-mcq` |
| [`item-defects/`](skills/item-defects/) | ข้อบกพร่องของข้อสอบ แยกไฟล์ตามชนิดข้อสอบ พร้อมวิธีแก้ของแต่ละข้อ | `make-exam`, `critique-mcq`, `analyze-results` |
| [`learning-outcomes/`](skills/learning-outcomes/) | อะไรทำให้ผลลัพธ์การเรียนรู้วัดได้ และตรวจ alignment สองทิศทางอย่างไร | `design-course`, `make-exam` |

และอีกหนึ่งโฟลเดอร์เป็น **primitive** — มีลำดับขั้นของตัวเอง แต่ถูกเรียกจาก*กลาง*ขั้นของ checklist ตัวอื่น
ทำงานจนจบแล้วคืนการควบคุมให้ขั้นนั้น ไม่มีขั้นสำรวจหรือขั้นตรวจปิดท้ายของตัวเอง

| primitive | ทำอะไร | ใครเรียก |
|---|---|---|
| [`grill-point/`](skills/grill-point/) | หยุดซักผู้ใช้ทีละรอบจนเข้าใจตรงกันก่อนเขียนเอกสารต้นทาง แล้วบันทึกการตัดสินใจที่ใช้ต่อได้เป็น decision record | `design-course`, `make-exam`, `make-practical`, `analyze-results`, `audit-brain` |

เริ่มจากศูนย์ให้พิมพ์เรียก `init-brain` ก่อน — มันสร้าง `AGENTS.md`, index, templates และสคริปต์ตรวจ
ซึ่งเป็น "สิ่งที่ skill ตัวอื่นไปอ่านตอนรัน"

### skill ตัวใหม่จะอยู่กลุ่มไหน

ตัดสินที่ **สิ่งที่ skill เปลี่ยนแปลงเมื่อทำงานเสร็จ ไม่ใช่หัวข้อของงาน** — หัวข้อเป็นความรู้สึก แต่ผลลัพธ์ชี้ได้ด้วยนิ้ว

1. ผลลัพธ์คือ **เนื้อหาในคลังความรู้** → *งานกับคลังความรู้*
2. ผลลัพธ์คือ **เอกสารที่คนอื่นเอาไปเรียนหรือใช้ประเมิน** → *งานสอนและวัดผล*
3. เข้าได้ทั้งสองข้อ → ตัดสินด้วยคำถาม "ถ้าลบผลลัพธ์นั้นทิ้ง **ใคร** เดือดร้อน"
4. เข้าไม่ได้เลยสักข้อ → นั่นคือสัญญาณของ **กลุ่มใหม่** ไม่ใช่สัญญาณว่าจัดผิด

โฟลเดอร์ยังแบนราบอยู่ใต้ [`skills/`](skills/) โดยตั้งใจ — เหตุผลอยู่ใน
[`docs/adr/0003`](docs/adr/0003-group-by-output-defer-the-folders.md)

## วิธีใช้

**Claude Code (ปลั๊กอิน)** — ติดตั้งทั้งชุด และอัปเดตได้ในคำสั่งเดียว

```
/plugin marketplace add seraght/claude-skills
/plugin install knowledge-keeper@seraght
```

**agent ตัวอื่น หรืออยากได้ทีละตัว** — คัดลอกโฟลเดอร์ที่ต้องการจาก `skills/` ไปไว้ที่
`<โปรเจกต์>/.claude/skills/<ชื่อ>/` (หรือที่ที่ agent ของคุณอ่าน skill) แล้วใช้ได้เลย ไม่ต้องแก้ path

ข้อยกเว้นคือ skill ที่อ่าน reference skill ต้องพาตัวที่มันอ่านไปด้วย —
`init-brain` กับ `audit-brain` ต้องไปพร้อม `brain-anatomy` และ `grill-point` (องค์ประกอบที่ 12 ใช้รูปแบบ decision record ของมัน)
`make-exam` กับ `make-practical` ต้องไปพร้อม `assessment-layout`, `item-defects`, `learning-outcomes` และ `grill-point`
`critique-mcq` ต้องไปพร้อม `assessment-layout` และ `item-defects`
`analyze-results` ต้องไปพร้อม `assessment-layout`, `item-defects`, `learning-outcomes` และ `grill-point`
ส่วน `design-course` ต้องไปพร้อม `learning-outcomes` และ `grill-point`

ถ้าโปรเจกต์ปลายทางยังไม่มีไฟล์กติกา (`AGENTS.md` / `CLAUDE.md`) หรือยังไม่มีโครงสร้างคลัง
skill จะถามหาข้อมูลที่จำเป็นระหว่างทาง —
ถ้าไม่อยากตอบซ้ำทุกครั้ง ให้เรียก `init-brain` สักครั้งเพื่อวางกติกาไว้ให้ตัวอื่นอ่าน

## แพทเทิร์นที่ใช้ (สำคัญกว่าตัวไฟล์เอง)

ทุก skill ในนี้ตามแพทเทิร์นเดียวกัน:

1. **Runtime discovery แทน hard-code** — ขั้นแรกของทุก skill คืออ่าน **ไฟล์กติกาของ agent**
   (`AGENTS.md` หรือ `CLAUDE.md`) และโครงสร้างจริงของโปรเจกต์ปลายทางก่อนตัดสินใจอะไรทั้งสิ้น **กติกาของโปรเจกต์ override ค่า default ของ skill เสมอ**
   คลุมเครือเมื่อไหร่ให้ถามผู้ใช้ ไม่ใช่เดา — จึงย้ายไปวางที่ไหนก็ใช้ได้โดยไม่ต้องแก้ไฟล์
   ขั้นนี้เขียนซ้ำเหมือนกันทุกตัวอักษรในทุก skill โดยตั้งใจ เพื่อให้คัดลอกโฟลเดอร์เดียวก็ยังรันได้
   ([ADR 0005](docs/adr/0005-duplication-buys-portability.md))
2. **skill = checklist เรียงลำดับ ไม่ใช่ที่เก็บกติกา** — และเป็น checklist ที่รันจบในตัว
   เรียก skill อื่นได้เฉพาะเมื่อสิ่งที่เรียกเป็น **reference ล้วน** (เช่น `brain-anatomy`) หรือเป็น **primitive**
   (เช่น `grill-point`) ซึ่งไม่มีขั้นสำรวจและขั้นตรวจของตัวเอง ทำจบแล้วคืนการควบคุม — reference ชี้ไปหารูปแบบ
   ที่อยู่ใน primitive ได้เช่นกัน — แต่ไม่ใช่ checklist อีกตัว
   ที่จะพา checklist มาพันกัน ([ADR 0006](docs/adr/0006-how-a-skill-is-reached-and-when-it-is-split.md),
   [ADR 0016](docs/adr/0016-agreement-is-not-understanding.md))
3. **จบด้วยขั้นตรวจแบบมีเงื่อนไข** — โปรเจกต์มีสคริปต์ตรวจก็รัน ไม่มีก็ตรวจตาม checklist ที่ skill ระบุไว้
   ไม่ปล่อยให้ "รู้สึกว่าเสร็จ" เป็นเกณฑ์จบงาน
4. **ภาษาอังกฤษเป็น default** ในเนื้อหา skill ส่วน trigger ภาษาไทยเก็บไว้ใน `description`
   เพื่อให้ agent เรียก skill ถูกตัวเมื่อผู้ใช้พิมพ์ไทย — และ trigger เขียนเป็นภาษาธรรมชาติล้วน
   ไม่อ้างชื่อคำสั่ง `/xxx` เพราะ agent บางตัวไม่มีระบบคำสั่งแบบนั้น
   `description` ยาวได้ราว 30 คำ เพราะมันถูกโหลดทุกเทิร์นไม่ว่าจะได้ใช้หรือไม่
   หน้าที่ของมันคือทำให้ agent *เรียกถูกตัว* ไม่ใช่เล่าว่า skill ทำอะไรบ้าง — เรื่องนั้น body เล่าอยู่แล้ว
5. **สองชั้นของการเรียก** — skill ที่ผู้ใช้พิมพ์ไทยแล้วต้องยิงถูกตัวเป็น model-invoked
   ส่วน skill ที่ *สร้าง* ของทั้งโครง หรือผู้ใช้รู้อยู่แล้วว่าจะเรียกเมื่อไร เป็น user-invoked (พิมพ์ชื่อเอง)
   ไม่ต้องจ่ายค่า `description` ที่ค้างอยู่ในบริบททุกเทิร์น ([ADR 0006](docs/adr/0006-how-a-skill-is-reached-and-when-it-is-split.md))
6. **Progressive disclosure** — ความรู้อ้างอิงที่ไม่ใช่ทุกครั้งต้องใช้ แยกเป็นไฟล์ข้างเคียงแล้วชี้จาก SKILL.md
   (`make-exam/ASSESSMENT-REFERENCE.md`, `critique-mcq/MCQ-CRITIQUE-REFERENCE.md`, และ `brain-anatomy/` ที่ถูกดันออกไปเป็น skill เต็มตัว) — ตัว checklist หลักจะได้ไม่บวม
7. **เครื่องมือภายนอกคือตัวเร่ง ไม่ใช่เงื่อนไขจำเป็น** — ทุกขั้นระบุ *เป้าหมาย* แล้วให้ทางที่ agent ทำได้
   ด้วยความสามารถติดตัวเป็นค่าตั้งต้น มี tool ในเครื่องค่อยใช้เพื่อความเร็ว คนที่ไม่ได้สาย IT
   จึงเริ่มใช้ได้โดยไม่ต้องติดตั้งอะไรก่อน ([ADR 0002](docs/adr/0002-external-tools-are-accelerators-not-prerequisites.md))
8. **Shape is shared, process is copied** — *process* คือสิ่งที่ skill ตัวนั้นทำตามลำดับของมันเอง
   คัดลอกใส่ทุกไฟล์และถือให้เหมือนกันเป๊ะ ส่วน *shape* คือโครงสร้างของ artifact ที่หลาย skill
   อ่านและเขียนร่วมกัน อยู่บ้านเดียวในรูป reference skill แล้วเรียกด้วยชื่อ
   จังหวะสร้างบ้านคือ **ตอนมี skill ตัวที่สอง** ที่ต้องรู้ shape เดียวกัน
   ([ADR 0007](docs/adr/0007-shape-is-shared-process-is-copied.md))
9. **ขั้นตรวจต้องทิ้งหลักฐานไว้** — ขั้นที่สั่งให้ "ดู" หรือ "ถามตัวเอง" แล้วไม่มีอะไรตกออกมา
   จะแยกไม่ออกระหว่างรอบที่ทำจริงกับรอบที่ข้าม ทุกขั้นตรวจจึงต้องนับเป็นตัวเลข เขียนตารางลงไฟล์
   และรายงานจำนวนของทุกกลุ่มรวมกลุ่มที่ไม่เจออะไรเลย ([ADR 0008](docs/adr/0008-a-check-that-leaves-no-evidence-did-not-run.md))
   — และเกณฑ์ตัวเลขของขั้นตรวจต้องมาจาก skill เอง เกณฑ์ที่ skill ไม่ให้ไว้คือเกณฑ์ที่ agent จะตั้งเองแบบหลวม ๆ
   ([ADR 0018](docs/adr/0018-a-threshold-the-skill-does-not-give-is-one-the-agent-invents.md))
10. **กฎที่ตรวจไม่ได้คือกฎที่จะเพี้ยน** — `python _scripts/check.py` คือขั้นตรวจของเรปโปนี้เอง
   ทุกกฎในนั้นมีอยู่เพราะของจริงเคยเพี้ยนมาแล้วหนึ่งครั้ง ADR ฉบับใหม่ที่บังคับอะไรกับไฟล์ skill
   ควรเพิ่มกฎลงไปด้วย
11. **จริงกับทุกคน หรือจริงแค่ที่นี่** — เกณฑ์ตัดสินว่าความรู้ก้อนหนึ่งควรติดไปกับ skill หรือควรอยู่ในคลัง
   *จริงกับทุกคน* (สูตร เกณฑ์ตัวเลข ตารางวินิจฉัย) ติดไปกับ skill เพราะเครื่องที่ไม่มีคลังก็ต้องได้มันไปด้วย
   *จริงแค่ที่นี่* (สเกลของสถาบัน ฟอร์มที่ต้องส่ง PLO ของหลักสูตร) อยู่ในคลัง เพราะมันผิดทันทีที่ย้ายที่
   เกณฑ์นี้ไม่ใช่ "ค้นไว้แล้วหรือยัง" — ของที่ค้นไว้แล้วอาจเป็นความรู้สากลที่ค้างอยู่ผิดที่
   ([ADR 0013](docs/adr/0013-true-everywhere-or-true-here.md))
12. **ตกลงไม่เท่ากับเข้าใจ** — ทุก checklist แสดงแผนให้ผู้ใช้เห็นหลังขั้นสำรวจ แล้วรอให้เริ่ม
   ขั้นที่เขียนเอกสารซึ่งงานอื่นสร้างต่อ หรือที่ต้องใช้ข้อเท็จจริงที่มีแต่ผู้ใช้รู้ เป็น **grill point**:
   หยุดซักทีละรอบจนเข้าใจตรงกัน *แม้ทุกการตรวจจะผ่าน* เพราะการตัดสินใจเป็นของผู้ใช้ —
   ต่างจาก gate ที่หยุดเมื่อไม่ผ่าน และต่างจากการรออนุมัติ ซึ่งใช้เมื่อสิ่งที่วางให้ดูประเมินได้ด้วยตัวมันเอง
   คำตอบที่อยู่นานกว่าเอกสารฉบับนั้นถูกเก็บเป็น decision record ในคลัง
   ([ADR 0016](docs/adr/0016-agreement-is-not-understanding.md), [ADR 0017](docs/adr/0017-the-vault-keeps-its-reasons.md))
