# claude-skills

ชุด checklist ที่ agent เดินตามได้ สำหรับ **งานความรู้ที่ทำซ้ำเป็นรอบ** — งานที่ลำดับขั้นสลับไม่ได้,
ข้ามขั้นแล้วพังแบบไม่ส่งเสียง, และจบลงด้วยเอกสารที่ต้องไปอยู่ถูกที่
ทุกตัวอ่านกติกาของโปรเจกต์ปลายทางตอนรัน จึงย้ายไปวางที่ไหนก็ใช้ได้โดยไม่ต้องแก้ไฟล์

## รายการ skill

### งานกับคลังความรู้

ผลลัพธ์คือ *เนื้อหาในคลัง* — โครงสร้าง, digest, index, roll-up

| skill | ทำอะไร |
|---|---|
| [`init-brain/`](skills/init-brain/) | สร้างคลังใหม่ — สัมภาษณ์เฉพาะส่วนที่ต่างกันในแต่ละคลัง แล้ว scaffold ทั้ง 11 องค์ประกอบ **(พิมพ์เรียกเองเท่านั้น)** |
| [`audit-brain/`](skills/audit-brain/) | ตรวจสุขภาพคลังเดิมด้วยเกณฑ์ 11 องค์ประกอบ → ให้คะแนน → รายงาน → แก้เฉพาะที่อนุมัติ |
| [`digest/`](skills/digest/) | นำเข้าเอกสารดิบจากโฟลเดอร์พักเข้าคลัง — อ่านเนื้อหาจริง, ผ่านด่านความเป็นส่วนตัว/ลิขสิทธิ์, เขียน digest, ลงทะเบียน |
| [`new-subject/`](skills/new-subject/) | เปิดหัวข้อใหม่ในคลัง — skeleton, ย่อยเอกสารตั้งต้น, เขียนไฟล์ภาพรวม, ลงทะเบียนใน index |
| [`update-portfolio/`](skills/update-portfolio/) | ซิงก์เอกสารสรุปที่คร่อมหลายแหล่ง — เทียบทีละหัวข้อกับต้นทาง + บันทึกประวัติการตัดสินใจ |

### งานสอนและวัดผล

ผลลัพธ์คือ *เอกสารที่คนอื่นเอาไปเรียนหรือใช้ประเมิน*

| skill | ทำอะไร |
|---|---|
| [`make-exam/`](skills/make-exam/) | ออกข้อสอบตามลำดับที่ห้ามสลับ — blueprint → items → answer key → rubric |
| [`critique-mcq/`](skills/critique-mcq/) | วิพากษ์ข้อสอบปรนัยก่อนนำไปใช้ — วัดตัวเลือกก่อน แล้วรายงานทั้งรายข้อและทั้งฉบับ พร้อมฉบับแก้ รออนุมัติก่อนแตะไฟล์ |

อีกหนึ่งโฟลเดอร์คือ [`brain-anatomy/`](skills/brain-anatomy/) ซึ่งไม่ใช่ checklist แต่เป็น **reference skill** —
เก็บนิยาม 11 องค์ประกอบไว้ที่เดียวให้ `init-brain` กับ `audit-brain` เรียกใช้ร่วมกัน

เริ่มจากศูนย์ให้พิมพ์เรียก `init-brain` ก่อน — มันสร้าง `AGENTS.md`, index, templates และสคริปต์ตรวจ
ซึ่งเป็น "สิ่งที่ skill ตัวอื่นไปอ่านตอนรัน"

### skill ตัวใหม่จะอยู่กลุ่มไหน

ตัดสินที่ **สิ่งที่ skill เปลี่ยนแปลงเมื่อทำงานเสร็จ ไม่ใช่หัวข้อของงาน** — หัวข้อเป็นความรู้สึก แต่ผลลัพธ์ชี้ได้ด้วยนิ้ว

1. ผลลัพธ์คือ **เนื้อหาในคลังความรู้** → *งานกับคลังความรู้*
2. ผลลัพธ์คือ **เอกสารที่คนอื่นเอาไปเรียนหรือใช้ประเมิน** → *งานสอนและวัดผล*
3. เข้าได้ทั้งสองข้อ → ตัดสินด้วยคำถาม "ถ้าลบผลลัพธ์นั้นทิ้ง **ใคร** เดือดร้อน"
4. เข้าไม่ได้เลยสักข้อ → นั่นคือสัญญาณของ **กลุ่มใหม่** ไม่ใช่สัญญาณว่าจัดผิด

โฟลเดอร์ยังแบนราบอยู่ใต้ [`skills/`](skills/) โดยตั้งใจ — เหตุผลอยู่ใน
[`docs/adr/0003`](docs/adr/0003-group-by-output-defer-the-folders.md)

## วิธีใช้

**Claude Code (ปลั๊กอิน)** — ติดตั้งทั้งชุด และอัปเดตได้ในคำสั่งเดียว

```
/plugin marketplace add seraght/claude-skills
/plugin install knowledge-keeper@seraght
```

**agent ตัวอื่น หรืออยากได้ทีละตัว** — คัดลอกโฟลเดอร์ที่ต้องการจาก `skills/` ไปไว้ที่
`<โปรเจกต์>/.claude/skills/<ชื่อ>/` (หรือที่ที่ agent ของคุณอ่าน skill) แล้วใช้ได้เลย ไม่ต้องแก้ path

ข้อยกเว้นเดียว: `init-brain` และ `audit-brain` ต้องไปพร้อม `brain-anatomy` เพราะทั้งคู่อ่านนิยาม 11 องค์ประกอบจากมัน

ถ้าโปรเจกต์ปลายทางยังไม่มีไฟล์กติกา (`AGENTS.md` / `CLAUDE.md`) หรือยังไม่มีโครงสร้างคลัง
skill จะถามหาข้อมูลที่จำเป็นระหว่างทาง —
ถ้าไม่อยากตอบซ้ำทุกครั้ง ให้เรียก `init-brain` สักครั้งเพื่อวางกติกาไว้ให้ตัวอื่นอ่าน

## แพทเทิร์นที่ใช้ (สำคัญกว่าตัวไฟล์เอง)

ทุก skill ในนี้ตามแพทเทิร์นเดียวกัน:

1. **Runtime discovery แทน hard-code** — ขั้นแรกของทุก skill คืออ่าน **ไฟล์กติกาของ agent**
   (`AGENTS.md` หรือ `CLAUDE.md`) และโครงสร้างจริงของโปรเจกต์ปลายทางก่อนตัดสินใจอะไรทั้งสิ้น **กติกาของโปรเจกต์ override ค่า default ของ skill เสมอ**
   คลุมเครือเมื่อไหร่ให้ถามผู้ใช้ ไม่ใช่เดา — จึงย้ายไปวางที่ไหนก็ใช้ได้โดยไม่ต้องแก้ไฟล์
   ขั้นนี้เขียนซ้ำเหมือนกันทุกตัวอักษรในทุก skill โดยตั้งใจ เพื่อให้คัดลอกโฟลเดอร์เดียวก็ยังรันได้
   ([ADR 0005](docs/adr/0005-duplication-buys-portability.md))
2. **skill = checklist เรียงลำดับ ไม่ใช่ที่เก็บกติกา** — และเป็น checklist ที่รันจบในตัว
   เรียก skill อื่นได้เฉพาะเมื่อสิ่งที่เรียกเป็น **reference ล้วน** (เช่น `brain-anatomy`) ไม่ใช่ checklist อีกตัว
   ที่จะพา checklist มาพันกัน ([ADR 0006](docs/adr/0006-how-a-skill-is-reached-and-when-it-is-split.md))
3. **จบด้วยขั้นตรวจแบบมีเงื่อนไข** — โปรเจกต์มีสคริปต์ตรวจก็รัน ไม่มีก็ตรวจตาม checklist ที่ skill ระบุไว้
   ไม่ปล่อยให้ "รู้สึกว่าเสร็จ" เป็นเกณฑ์จบงาน
4. **ภาษาอังกฤษเป็น default** ในเนื้อหา skill ส่วน trigger ภาษาไทยเก็บไว้ใน `description`
   เพื่อให้ agent เรียก skill ถูกตัวเมื่อผู้ใช้พิมพ์ไทย — และ trigger เขียนเป็นภาษาธรรมชาติล้วน
   ไม่อ้างชื่อคำสั่ง `/xxx` เพราะ agent บางตัวไม่มีระบบคำสั่งแบบนั้น
   `description` ยาวได้ราว 30 คำ เพราะมันถูกโหลดทุกเทิร์นไม่ว่าจะได้ใช้หรือไม่
   หน้าที่ของมันคือทำให้ agent *เรียกถูกตัว* ไม่ใช่เล่าว่า skill ทำอะไรบ้าง — เรื่องนั้น body เล่าอยู่แล้ว
5. **สองชั้นของการเรียก** — skill ที่ผู้ใช้พิมพ์ไทยแล้วต้องยิงถูกตัวเป็น model-invoked
   ส่วน skill ที่ *สร้าง* ของทั้งโครง หรือผู้ใช้รู้อยู่แล้วว่าจะเรียกเมื่อไร เป็น user-invoked (พิมพ์ชื่อเอง)
   ไม่ต้องจ่ายค่า `description` ที่ค้างอยู่ในบริบททุกเทิร์น ([ADR 0006](docs/adr/0006-how-a-skill-is-reached-and-when-it-is-split.md))
6. **Progressive disclosure** — ความรู้อ้างอิงที่ไม่ใช่ทุกครั้งต้องใช้ แยกเป็นไฟล์ข้างเคียงแล้วชี้จาก SKILL.md
   (`make-exam/ASSESSMENT-REFERENCE.md`, `critique-mcq/MCQ-CRITIQUE-REFERENCE.md`, และ `brain-anatomy/` ที่ถูกดันออกไปเป็น skill เต็มตัว) — ตัว checklist หลักจะได้ไม่บวม
7. **เครื่องมือภายนอกคือตัวเร่ง ไม่ใช่เงื่อนไขจำเป็น** — ทุกขั้นระบุ *เป้าหมาย* แล้วให้ทางที่ agent ทำได้
   ด้วยความสามารถติดตัวเป็นค่าตั้งต้น มี tool ในเครื่องค่อยใช้เพื่อความเร็ว คนที่ไม่ได้สาย IT
   จึงเริ่มใช้ได้โดยไม่ต้องติดตั้งอะไรก่อน ([ADR 0002](docs/adr/0002-external-tools-are-accelerators-not-prerequisites.md))

## ที่มา

สกัดครั้งแรกจากคลังความรู้ส่วนตัวเมื่อ 2026-08-12 ตอนนั้นยังเป็น "ตัวอย่าง pattern ที่ต้องแก้ path เองก่อนใช้"
ต่อมาเขียนใหม่ทั้งหมดให้พกพาได้จริง ([ADR 0001](docs/adr/0001-generalize-skills-for-portability.md))
แล้วจึงตัดกรอบ "second brain" ออกจากนิยาม เพราะของจริงในคลังกว้างกว่านั้น
([ADR 0003](docs/adr/0003-group-by-output-defer-the-folders.md))
