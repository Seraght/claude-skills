# make-exam — build a written exam set

Scope: examinations answered on paper or on screen — selected-response, constructed-response, and matching items. A practical or performance examination is a different chain and belongs to the `make-practical` skill: its blueprint is an alignment matrix of tasks rather than a grid of topics by level, it has no answer key of distractor rationales, and its scoring instrument and its markers are the design rather than a late step.

This skill is an ordered checklist: each step opens when the one before it has produced its result. Each artifact is derived from the one before it: items that precede a blueprint end up weighted by what was easy to write. The folder shape and what the file numbers mean are in the `assessment-layout` skill; what makes an outcome assessable is in the `learning-outcomes` skill; what a defective item looks like is in the `item-defects` skill; the assessment principles behind each step are in [ASSESSMENT-REFERENCE.md](./ASSESSMENT-REFERENCE.md) — read it before step 5.

## Steps

1. **Discover the project's conventions** — read the host project's agent instructions file (`AGENTS.md`, or `CLAUDE.md`) and inspect an existing exam set: folder layout, file naming, available templates, and whether the project carries its own assessment reference. A project's own assessment rules override [ASSESSMENT-REFERENCE.md](./ASSESSMENT-REFERENCE.md) and the `item-defects` skill; its templates override the document shapes below.
2. **Open the exam set folder** — one folder per exam, in the place and under the name the `assessment-layout` skill gives, unless the vault's own rule says otherwise.
3. **Read the course definition, and check the outcomes before building on them** — the syllabus or its digest supplies the learning outcomes, the grade weighting, and the teaching hours per topic; the teaching plan or timetable, where the project holds one, supplies the hours each outcome actually receives; the programme-level outcomes the course is mapped to supply what the course owes upward. Take these from the documents rather than estimating, and name any that are missing rather than inferring them. Then check each outcome against the `learning-outcomes` skill: the four ways a verb fails, and whether teaching hours stand behind it. Check the whole set, not one outcome at a time: the mapping in both directions is a property of the set and fails silently when each outcome is read alone. **Where an outcome fails any of those checks, stop and put it to the user.** A compound outcome produces two exams stapled together and reads that way; an unobservable one has no defensible item; an outcome that reaches no programme outcome is unassessed however the marks total. Then ask **whose outcome it is**: where the user owns it, the failure is fixed before the blueprint is drawn, because a paper built on a broken outcome cannot be repaired later. Where the outcome belongs to an approved syllabus or to another person, the user cannot fix it and the run is not blocked by it — report what it would have to become, get the user's acknowledgement to proceed on it as it stands, and record the limitation in the blueprint as an open item rather than a settled one.
4. **Research only what is missing** — if the exam needs subject knowledge neither the course documents nor the assessment reference supply, gather it and record it in `00-research.md` with sources.
5. **Write the blueprint** (`01-blueprint.md`) — in the shape the `assessment-layout` skill gives. Every cell maps to a learning outcome and carries three things: its item count, its marks, and **the item format the cell's level can actually be reached by** — the format is a column of the table or an entry in every cell, never one declaration covering the whole paper, because the check it exists for is made cell by cell — a format left to be decided at writing time is decided by what is quickest to write, and a Create-level cell filled with selected-response items leaves its outcome unassessed while the totals still reconcile. Marks per topic track that topic's teaching hours, and totals reconcile with the course's grade weighting.
6. **Write the items** (`02-items.md`) — each item tagged with its learning outcome, its cognitive level, and the cell it fills, in the format that cell specifies. The blueprint is the specification. Writing more items than a cell needs is fine — a surplus to choose from is normal practice — but every item belongs to a cell, and the reconciliation happens when the paper is assembled, not here. On selected-response items write the stem first, then the distractors, then the correct option — writing the correct option first is what makes it the longest and the most qualified of the four.
7. **Measure every item, and write the table down** — before the answer key exists, build the measurement table the `item-defects` skill describes and record it in the exam set as the next free authoring file (default `06-measurements.md`). **Count rather than estimate** — the length of every option **in characters excluding spaces**, never in words, since a word count measures nothing in a language that does not put spaces between words and a space is a phrase break rather than a character in one that does: how many options carry a parenthesis, a hedge, a negation or an absolute term, which words the stem shares with the key alone, and what sits in the position the key points at. Where a check answers yes or no rather than producing a number, the cell holds the matched span — the string, which option carries it, in how many options it appears — never a tick or the words "none found". **One item, one row.** Then read the counts against `COMMON-DEFECTS.md` and against the file for each item's own format, and rewrite what they find — re-measuring anything rewritten, because repairs introduce their own flaws. Report a count for every group including the groups that found nothing: a step that produces no table did not run, and a group with no count was not looked at.
8. **Write the answer key** (`04-answer-key.md`) — every item, with the rationale for each distractor on selected-response items.
9. **Write the rubric** (`05-rubric.md`) — for every constructed-response item, with observable criteria whose weights sum to the item's marks.
10. **Assemble the paper** (`03-paper.md` where the project separates the examinee-facing paper from the item bank) — decide which items the exam takes, then reconcile the blueprint against exactly those: marks per topic, the level distribution, and the format of each cell are recomputed for the selected set. A blueprint balanced over a larger pool says nothing about the subset drawn from it.
11. **Verify before finishing, and record what has not happened yet** — run the project's check script where one exists, then confirm: every learning outcome passed the step 3 checks, or was raised with the user and recorded as an open item; the assembled paper's marks total to the course's grade weighting; every item traces to a learning outcome and to a cell whose format it matches; the measurement table is in the exam set and every group reports a count including the empty ones; every item appears in the answer key; and every constructed-response item has rubric criteria. Then close the set by **writing into it** that this skill produces an exam set and not a cleared one: the binding review runs on the assembled paper, at the stage the `assessment-layout` skill numbers `1x`, and it is a separate pass by design, because a check run by whoever wrote the items, in the session that wrote them, is the weakest form of the check. Record it as an unticked item in the exam set's own closing check, naming the review skill the project uses — `critique-mcq` for selected-response papers. A handoff that exists only as a sentence in the session is a step that leaves no evidence, which is the failure every other check in this skill is written to avoid.
