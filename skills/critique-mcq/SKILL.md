# critique-mcq — critique multiple-choice items

This skill is an ordered checklist: each step opens when the one before it has produced its result. Every finding rests on a measurement that already exists. It produces a critique and proposed rewrites; it does not change anything until the author approves. The folder shape and what the file numbers mean are in the `assessment-layout` skill; the taxonomy, the measurements, and the rules that keep a critique from over-reporting are in [MCQ-CRITIQUE-REFERENCE.md](./MCQ-CRITIQUE-REFERENCE.md) — read it before step 5.

Scope: selected-response items with a single best answer. Constructed-response, practical, and matching items are listed as not reviewed rather than judged against this taxonomy.

The binding pass is the one run on the **assembled paper** — the items as they will be printed, after any selection and editing. Running on an item pool beforehand is useful for weeding, but a pool that passed says nothing about the paper drawn from it: selecting breaks the blueprint, and editing voids every earlier check.

## Steps

1. **Discover the project's conventions** — read the host project's agent instructions file (`AGENTS.md`, or `CLAUDE.md`) and inspect the exam folder for: the assessment layout, the language the vault writes its documents in, the institution's cognitive-level scale and its critique paperwork, and the item rules the project or the institution fixes, such as the required number of options. A project's own assessment rules override [MCQ-CRITIQUE-REFERENCE.md](./MCQ-CRITIQUE-REFERENCE.md); an item is not flawed for obeying a rule the project imposes; and the report is written in the vault's language, defaulting to the language of the paper.
2. **Locate the paper and its anchors** — the assembled paper **in the form it will be given to examinees**, the answer key as it stands now, the blueprint, the learning outcomes, the item pool the paper was drawn from, and the course sources the content can be checked against. Name every one of these that is missing before going further: without a blueprint and an outcome list, step 8 cannot run and the report must say so rather than infer the outcomes an item was meant to serve; without course sources, content correctness goes unverified and the report says that too.
3. **Read the rendered paper once and establish provenance** — read the printed or exported form, not only the text pulled out of a word-processor file: equations, figures, and marks carried by formatting live outside the text stream, and an extraction that drops them makes an intact item look broken. An item whose stem or options come out incomplete is a finding about the reading tool until the rendered page says otherwise — never a finding about the item. Match each item back to the pool and mark it *used unchanged*, *edited after selection*, or *written outside the set*. Items in the last two groups carry no valid earlier check, whatever was run on the pool. Nothing is recorded as a finding in this pass.
4. **Measure every item** — build the measurement table described in the reference: option lengths, terms recurring across options, words shared between stem and key only, absolute and vague terms, negation, numeric ranges, exhaustiveness, whether the lead-in is closed, and what sits in the position the key points at. Count rather than estimate, in characters where the language does not separate words; a script or a tokenizer is a speed-up here, not a requirement. Keep the table — it is the evidence the findings are quoted from, and it is published with the report, so a pass that did not run is visible instead of silently absent.
5. **Pass 1 — cues that reward test-wiseness** — work through Group A of the reference, reading each check off the measurement table rather than off an impression of the item.
6. **Pass 2 — irrelevant difficulty** — work through Group B: what makes the item hard for reasons unrelated to what it measures.
7. **Pass 3 — congruence, level, and correctness** — work through Group C against the anchors from step 2, starting with whether the keyed answer survives a check against the course's own sources. Record the level on the institution's scale.
8. **Pass 4 — the paper as a whole** — work through Group D, beginning with the key-to-position check on every item, then reconciling the blueprint against the items actually selected. These defects appear only after selection and reordering, so they are checked last and never skipped because the items passed individually.
9. **Triage the findings** — assign Block, Revise, or Note; drop any finding that cannot quote the span it is about; merge findings a single rewrite resolves. A paper that comes back with more findings per item than it has options is over-reported, and is re-triaged rather than delivered.
10. **Write the critique** — into the exam set's review-stage file (default `10-critique.md`), in the shape the reference's *Reporting* section specifies. The leading number is the lifecycle stage the vault assigns to review, rather than the next unused number in the folder — a review file numbered to follow the last authoring artifact claims to be the next step of a chain it is not part of. Find that exam set by course, year, and exam in the vault rather than only in the folder the paper sits in: the paper and its exam set routinely live in different trees, and falling back to the paper's own folder scatters the review stage away from the artifacts it belongs with. Only where no exam set exists anywhere does the report go beside the paper as `<paper filename>-critique.md`.
11. **Stop for approval, then apply what is approved** — change nothing before the author decides, item by item or in bulk. Re-measure every rewritten item against step 4, because repairs introduce their own flaws, and re-run the key-to-position check after any option is reordered. Never change a keyed answer silently: a suspected miskey is reported for the author to confirm.
12. **Follow through and verify** — every accepted change propagates to the answer key, the blueprint, the rubric, and the paper. Run the project's check script where one exists, then confirm: the measurement table is in the report, every pass reports a count including the empty ones, every finding carries quoted evidence and a severity, every rewritten item was re-measured, every key matches the option it points at, and the blueprint reconciles against the items the paper actually contains.
