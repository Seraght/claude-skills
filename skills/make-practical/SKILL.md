# make-practical — build a practical exam set

This skill is an ordered checklist: each step opens when the one before it has produced its result. It is the sibling of `make-exam`, not a mode of it — a practical is a different chain. There is no item bank of stems and options, no answer key of distractor rationales, and the scoring instrument is the centre of the design rather than a late step. What replaces them is conditions, markers, and a standard.

The folder shape and what the file numbers mean are in the `assessment-layout` skill; what makes an outcome assessable is in the `learning-outcomes` skill; what a defective task looks like is in the `item-defects` skill; how a practical is built is in [PRACTICAL-REFERENCE.md](./PRACTICAL-REFERENCE.md) — read it before step 5.

## Steps

1. **Discover the project's conventions** — read the host project's agent instructions file (`AGENTS.md`, or `CLAUDE.md`) and inspect an existing exam set: folder layout, file naming, available templates, and whether the project carries its own assessment reference. A project's own assessment rules override [PRACTICAL-REFERENCE.md](./PRACTICAL-REFERENCE.md) and the `item-defects` skill; its templates override the document shapes below. The institution's constraints on rooms, equipment, marker availability, and sitting times are part of this step, because they decide what design is possible at all.
2. **Open the exam set folder** — one folder per examination, in the place and under the name the `assessment-layout` skill gives, unless the vault's own rule says otherwise.
3. **Read the course definition, and check the outcomes before building on them** — the syllabus or its digest supplies the outcomes, the grade weighting, and the teaching hours; the teaching plan supplies what learners have actually had the chance to practise; the programme outcomes supply what the course owes upward. Then check each outcome against the `learning-outcomes` skill. **Where an outcome fails those checks, stop and put it to the user.** A practical is the only instrument that can evidence a *create* or *perform* outcome, so an outcome that is compound — one half performable, the other not — splits the examination in two before a single task is written.
4. **Research the performance itself** — what a competent person actually does, what distinguishes competent from not, and the errors real learners make. Record it in `00-research.md` with sources. This is the largest step in a practical and the one most often skipped: a written paper can lean on the course material, but a task, its conditions, and the standard it is scored against all have to come from what the performance is really like.
5. **Write the alignment matrix** (`01-blueprint.md`) — one row per task: what the examinee does, what is observed, the criteria, the outcome it serves, the marks, and the time. This is the practical's blueprint, and it reaches upward: each row names the outcome and, where the project tracks them, the programme outcome behind it. Total marks reconcile with the course's grade weighting, and the whole examination fits the sitting time with the changeovers counted.
6. **Design the tasks and state their conditions** (`03-paper.md`, the examinee-facing copy) — one competence per task. Equipment, time limit, permitted references and tools, permitted assistance, and safety constraints are written into the task itself, not left as logistics: the same task under different conditions measures something different. Name every dependency on infrastructure and give it a fallback that earns the same marks. Where the examination runs in more than one sitting, alternate the content between sittings.
7. **Build the scoring instrument and set the standard** (`05-rubric.md`) — a checklist for procedure with a fixed order, a rating scale for judgement, both where a task has both halves; the choice is made per task, from the table in [PRACTICAL-REFERENCE.md](./PRACTICAL-REFERENCE.md). Criteria are observable, adjacent levels differ by something a marker can point at, and weights sum to the task's marks. Then set the pass standard, before the examination and by a stated method, and write the critical-error rule into the instrument where a safety violation or a critical error voids the attempt.
8. **Measure the design, and write the table down** — before the marker's copy is written, record in the exam set as the next free authoring file (default `06-measurements.md`): minutes per mark for every task, marks per outcome, the proportion of marks scored objectively against the proportion needing judgement, the number of independent tasks, and — where alternate forms exist — the result of working each form yourself under exam conditions. **Count rather than estimate.** Then read the counts against `PRACTICAL-DEFECTS.md` and `COMMON-DEFECTS.md` in the `item-defects` skill, and fix what they find. Report a count for every group including the groups that found nothing: a step that produces no table did not run.
9. **Write the marker's copy** (`04-answer-key.md`) — what the marker sets up, what they say, what they observe and score, what counts as a defensible response outside the expected set, and how the attempt is handled when a dependency fails. Include the calibration plan: which shared samples the marking team scores independently before marking starts, which work is double-marked, and where the agreement is recorded. A practical's marks live or die on marker consistency, and nothing else in the set defends it.
10. **Verify before finishing** — run the project's check script where one exists, then confirm: every outcome passed the step 3 checks or was raised with the user; every task traces to an outcome and every outcome the examination claims has at least one task; marks total to the course's grade weighting; the measurement table is in the exam set and every group reports a count including the empty ones; every task states its conditions; every task has a scoring instrument whose weights sum to its marks; the pass standard was set before the examination; and the marker's copy covers setup, scoring, and the calibration plan.
11. **Hand the examination on for review** — this skill produces an exam set, not a cleared one. The binding review runs at the stage the `assessment-layout` skill numbers `1x`, and it is a separate pass by design: a check run by whoever designed the tasks, in the session that designed them, is the weakest form of the check. Tell the user the set is ready for that review rather than treating step 10 as the last word.
